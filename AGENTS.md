# higgsphere

A local wall (bento / masonry) that shows **every AI-generated image and video** in one
place, newest at the top, with the exact prompt and the metadata of each generation.

Strictly local tool: **no SEO, no analytics, no outbound network calls.**

> This file is the single source of instructions, for every agent (Claude Code, Codex,
> Cursor, Copilot, Gemini CLI…). `CLAUDE.md` only imports it, and `.gemini/settings.json`
> points Gemini CLI to it: edit **here**. Like the skills, it is written in **English**
> (see "Code conventions").

---

## Core rule — the `generations/` folder

> **Every image and every video generated by an AI during an agent session must be
> written to the `generations/` folder at the project root, together with a `.json`
> metadata file of the same name.**

This rule is non-negotiable: it is the site's only data source. Media placed anywhere
else will never show up in the gallery.

```
generations/
  2026-08-31-nebula-drift.png      ← the media
  2026-08-31-nebula-drift.json     ← its metadata (same name, .json extension)
```

The site **detects new files on its own**, with no reload or restart: an SSE channel
(`/api/generations/stream`) watches the folder with a recursive `fs.watch`, and the page
updates within a second. So never restart the server after dropping a file.

### Sidecar naming convention

Both forms are accepted; the first is preferred:

| Media | Sidecar |
| --- | --- |
| `nebula-drift.png` | `nebula-drift.json` (extension **replaced**) |
| `nebula-drift.png` | `nebula-drift.png.json` (extension **appended**) |

Subfolders are allowed and walked recursively (`generations/2026-08/…`), which lets you
sort by date or by project. Accents and spaces in file names work.

## Sidecar `.json` schema

A flat JSON object. **Every field is optional** — a media file without a sidecar still
shows up on the wall — but fill in as many as possible: the prompt and the cost are the
reason this tool exists.

```json
{
  "prompt": "A vast nebula drifting through deep space, volumetric dust lanes lit from within",
  "negative_prompt": "blurry, watermark, extra fingers",
  "model": "imagen-4-ultra",
  "service": "Google Vertex AI",
  "width": 1024,
  "height": 1024,
  "duration": 5,
  "cost": 0.06,
  "currency": "USD",
  "created_at": "2026-08-31T10:31:00Z",
  "seed": 774213,
  "tags": ["space", "abstract", "wallpaper"],
  "notes": "Second pass, the first render was too saturated.",
  "poster": "nebula-drift-poster.jpg"
}
```

### Fields

| Field | Type | Role |
| --- | --- | --- |
| `prompt` | `string` | **The exact prompt** sent to the model, with no rewording or truncation. Feeds search and the lightbox. |
| `negative_prompt` | `string` | Negative prompt, if there is one. |
| `model` | `string` | Precise model identifier (`veo-3`, `flux-1.1-pro`, `dall-e-3`…), **and nothing else**: no post-processing step appended. Becomes a filter facet. |
| `service` | `string` | **The provider alone** (`OpenAI`, `Runway`, `Kie AI`…) — never the model in parentheses. Becomes a filter facet, and the axis of the spend page. |
| `width` / `height` | `number` | Dimensions in pixels. **Fill them in for videos** (see below). |
| `duration` | `number` | Duration in seconds, for videos. |
| `cost` | `number` | Estimated cost of **this generation**, in the currency **billed by the service** — don't convert it yourself. See "Costs and currencies". |
| `currency` | `string` | ISO code of the billed currency. `USD` if the field is missing. |
| `created_at` | `string` | ISO 8601 date. Failing that, the site uses the file's `mtime`. |
| `seed` | `number` \| `string` | Seed, if known. |
| `tags` | `string[]` | Free-form labels. Become filter facets. |
| `notes` | `string` | Useful context: what was tried, why this version was kept. |
| `poster` | `string` | Thumbnail for a video, a neighboring file name or a path relative to `generations/`. |

`service` and `model` answer two different questions — *who was paid* and *what was
called* — and the spend page groups them separately. Mixing them
(`"Kie AI (Kling 3.0 Omni)"`) invents a provider that doesn't exist and splits one
provider's total into several lines. A local step that follows the generation (crossfade,
crop, re-encode) belongs to neither: it goes in `notes` or in an extra field.

Any **extra** field (`steps`, `guidance`, `cfg`, `aspect_ratio`, `revised_prompt`…) is
kept and shown in the lightbox's "Other metadata" section. Feel free to add some — nothing
is lost.

### Tolerated aliases

The scanner accepts a few common variants, so as not to lose data when a sidecar comes from
elsewhere: `createdAt`/`date`/`timestamp` for `created_at`, `estimated_cost`/`price` for
`cost`, `provider`/`platform` for `service`, `model_name` for `model`, `labels` for `tags`,
and `size`/`resolution`/`dimensions` in the form `"1024x1024"` instead of
`width`/`height`.

### Dimensions: what to fill in

- **Images** — no need to provide them: the server reads the file header (PNG, JPEG, GIF,
  WebP, AVIF/HEIC) and derives the exact dimensions.
- **Videos** — **fill them in**. The server doesn't decode video containers. Without
  `width`/`height`, the tile is laid out as 16:9 and then corrected once the browser has
  read the file's metadata, which causes a slight layout jump.

### Costs and currencies

`cost` is an **estimated** cost, not an invoice. Fill in the model's public price for the
generation concerned (per image, per second of video, per megapixel depending on the
service). When unsure of the exact price, put the best possible estimate rather than
omitting the field — the total shown at the top of the wall only makes sense if coverage is
complete. If the cost is truly unknown, omit the field: it will show as `—` instead of
skewing the total.

**Always write the amount in the currency billed by the service**, with the matching code
in `currency` — most often `USD`. Don't convert anything by hand: the sidecar keeps the
original data, and the wall handles the display.

**The wall shows every amount in the currency chosen by the user** — euro, US dollar or
pound sterling, through the header selector; euro by default, and the choice is remembered
(`localStorage`, key `higgsphere.currency`). Conversion happens at display time only, from
the rate table in [src/lib/currency.ts](src/lib/currency.ts). These rates are **hard-coded**
— the tool makes no network calls — so they drift over time: reread them now and then. The
lightbox shows the original amount under the converted one, so the figure stays
verifiable; an amount already in the chosen currency is shown as is.

The euro is the **pivot currency**: sums, averages, shares and sorts are computed in euros
(the stores' `eur` fields), and conversion to the chosen currency only happens at
formatting time (`formatFromEur`, `formatCost` in [src/lib/format.ts](src/lib/format.ts)).
Never convert to the display currency before aggregating. To offer a new display currency,
add it to `DISPLAY_CURRENCIES`: the type of `RATES_TO_EUR` then refuses to compile until
its rate is present.

A currency missing from the table is never force-converted: the amount is shown in its own
currency, flagged, and excluded from the total, which then states how many amounts it
leaves out. To cover a new currency, add its rate to `RATES_TO_EUR`.

## Deleting a generation

The lightbox has a **"Delete this media"** button at the bottom of the panel, in the
"File" section. It asks for confirmation, then **permanently** deletes the media *and* its
sidecar — without going through the trash. The wall removes the tile immediately and the
lightbox **closes**: you're back on the wall, with no new media under the cursor at the
spot where you just confirmed a deletion.

On the server side, `DELETE /api/generations` expects a `{ "file": "<relative path>" }`
body. The route refuses anything that isn't a media file (a sidecar alone is never a
target) and any path that escapes `generations/`.

**The file goes, the spend stays.** Before erasing anything, the route archives the cost,
currency, date, provider and model in the spend ledger (see below). Deleting a media file
must never lower the total spent: the wall counts files, the spend page counts payments.

## The spend ledger

File `generations/.higgsphere-ledger.jsonl`: the record of **everything that was paid
for**. A generation is written to it **as soon as it appears in the folder**, not only when
it is deleted — otherwise an `rm` in the terminal would take the spend away with the file.
It starts with a dot, so the wall's scanner and the SSE watcher ignore it: it doesn't show
up in the gallery and triggers no rescan.

It is an append-only **event log**, never rewritten. Each line says what happened to a
generation, and the current state is rebuilt by folding the lines in order:

| Event | Written when |
| --- | --- |
| `created` | an unknown media file appears in `generations/` |
| `updated` | its cost, provider, model or path changes |
| `deleted` | it is deleted — `reason: "app"` from the lightbox, `reason: "missing"` if it disappeared from disk on its own |

Each generation carries an `id` assigned at birth, stable afterwards. The path can't serve
as a key: a file moves, and the same name can be regenerated after deletion.

`syncLedger()` is called on every read of `/api/generations` and `/api/spend` — so any view
of the wall keeps the ledger up to date. What matters:

- **The sidecar wins while the media exists.** It's the editable data; the ledger only
  takes over once the file is gone. A price fixed by hand in a `.json` produces an
  `updated`, it is never overwritten by history.
- **A sidecar written after its media** gives `created` with `cost: null`, then `updated`
  with the price. That's the normal case, not an anomaly.
- **A moved file isn't a new spend**: recognized by its name and size, it gives a path
  `updated` — not a delete + create pair that would count the money twice. Sorting into
  `generations/2026-08/` is therefore safe.
- **Disappearances are only recorded on a complete scan** (`index.warnings` empty): a
  momentarily unreadable folder produces a partial index, and burying history on that basis
  would be worse than missing an `rm`.
- **Syncs are serialized.** SSE, polling and two tabs scan in parallel; without a queue,
  two scans would record the same generation twice.
- Deletion from the app writes the event **before** erasing. If the write fails, nothing is
  deleted (`fail closed`); if the deletion then fails, the ledger is truncated back to its
  previous size, so that a media file still visible isn't counted as deleted.
- An unreadable line is skipped and reported, never fatal. The fold is tolerant: an
  `updated` or a `deleted` on an unknown identity opens the generation instead of failing.
- The ledger is **not versioned by default**: `/generations/*` is ignored, and the
  exception `!/generations/.higgsphere-ledger.jsonl` is commented out in `.gitignore` —
  uncomment it to commit the ledger. It's still the only data in the folder that nothing
  regenerates. Deleting it only loses the history of generations **already erased** —
  those still present re-register on the next scan.

## The spend page

`/stats`, reached from the "Spend" button in the wall's bar. It reads `GET /api/spend`,
which combines the sidecars still present and the ledger — so **everything that was paid
for**, whether the file still exists or not.

It shows, in order: the total, the average cost and the date of the latest spend, a
timeline of bars stacked by provider (per day, or per month beyond a 75-day span), one card
per provider with its share of the total and the breakdown by model, then the full spend
log grouped by date, newest first. Provider colors are assigned by spend rank and don't
change when filtering.

The only filter is the provider. **Deleted generations can't be hidden**: it's the file
that disappeared, not the payment — hiding them would make the total wrong.

The same currency rules as elsewhere apply: display in the chosen currency, unconvertible
amounts excluded from the total and flagged, generations without `cost` counted as such
rather than as zeros.

## Interface languages

The interface exists in English, French and Spanish; the selector is in the header of every
page ([Preferences.svelte](src/lib/components/Preferences.svelte)). Only the interface is
translated, never the sidecar data (see "Behaviors to preserve"). The rules for writing
texts are in "Code conventions".

The language is chosen in this order: the remembered choice (`localStorage`, key
`higgsphere.locale`), then the browser's first supported language, then English. It is
resolved synchronously when the module loads, before the first render: the page never shows
for an instant in another language. There is no i18n library, in line with the "no runtime
dependency" rule.

To add a language:

1. Copy [src/lib/i18n/en.ts](src/lib/i18n/en.ts) to `src/lib/i18n/<code>.ts`, type the
   export as `Messages` and translate the values (instantiating `pluralizer('<code>')`).
2. Add it to `LOCALES` in [src/lib/i18n/index.svelte.ts](src/lib/i18n/index.svelte.ts),
   with its name written in its own language (`Deutsch`, not `German`).
3. Run `npm run check`: a missing key, an extra key or a mistyped parameter makes it fail.
4. Translate the README into `README.<code>.md` and add it to the links line at the top of
   every README.

## What to do for each generation

1. Write the media to `generations/`, with a descriptive lowercase-dashed name, ideally
   prefixed with the date: `2026-08-31-nebula-drift.png`.
2. Immediately write the `.json` sidecar of the same name, with **at least** `prompt`,
   `model`, `cost` and `created_at`.
3. Restart nothing: the wall updates on its own.
4. Never overwrite an existing media file to produce a variant — create a new file, and link
   the two through `notes` or a shared `tags`.

## Skills

The project provides skills in the `SKILL.md` format (YAML frontmatter + Markdown +
scripts). They live in [.agents/skills/](.agents/skills/), where Codex looks for them;
`.claude/skills` is a link to that folder, for Claude Code. **An agent that doesn't
load skills on its own must read the whole `SKILL.md` before acting** whenever the task
matches its description:

| Skill | When to use it |
| --- | --- |
| [kie-ai](.agents/skills/kie-ai/SKILL.md) | Generate an image or a video through Kie AI (Kling, Veo, Seedream, Nano Banana…), estimate a credit spend, check the quality of a generated video. **Paid**: forbidden until the user has set a budget (`kie ok <credits>`), see the skill's "Rule number one". |
| [video-loop](.agents/skills/video-loop/SKILL.md) | Turn a video from `generations/` into a seamless loop, locally with `ffmpeg`. Also read it **before** generating a video meant to loop. |

Scripts are called by their path from the project root
(`.agents/skills/kie-ai/scripts/kie.sh …`), whatever the agent.

## Running the project

```bash
npm run dev      # http://localhost:5173
npm run check    # svelte-check (types)
npm run build    # production build (adapter-node)
npm run preview  # serves the build
```

The watched folder is `./generations` by default; it can be moved with the
`GENERATIONS_DIR` environment variable (absolute path).

## Code conventions

- **Agent-facing files are written in English**: this file (and `CLAUDE.md`, which only
  imports it) and everything under [.agents/skills/](.agents/skills/) — `SKILL.md`,
  references, price data, script comments and messages. A new skill is written in English
  from the start.
- **Svelte 5 in runes mode** (`$state`, `$derived`, `$props`, `$effect`). No legacy syntax:
  events are written `onclick`, not `on:click`.
- **Comments in the application code (`src/`) are in French.** Identifiers, JSON field
  names and technical terms stay in English.
- **No hard-coded interface text.** Every visible label (including `title`, `aria-label`,
  `placeholder`) lives in the dictionaries in [src/lib/i18n/](src/lib/i18n/) and is read
  through `i18n.m`. A new text is added to `en.ts` first, then to **every** other language:
  `npm run check` fails as long as a key is missing. A text that depends on a value is a
  function; a plural goes through `plural()` (never `n > 1`); inline code is written between
  backticks and rendered with `Rich` — never HTML in a translation.
- **Formatting follows the language.** Dates, numbers and percentages go through
  [src/lib/format.ts](src/lib/format.ts), which reads `i18n.locale`; never write a
  hard-coded `Intl.*('fr-FR')`.
- **Server messages are in English.** They are diagnostics. An error a user can run into
  also carries a `code` (see `App.Error`), translated on the client.
- **The README exists in three languages** (`README.md`, `README.fr.md`, `README.es.md`).
  Any change to one is carried over to the other two.
- **SSR disabled** ([src/routes/+layout.ts](src/routes/+layout.ts)): the tool reads the disk
  on demand, and client-only rendering avoids sharing the store between requests.
  Consequence: the browser receives an empty document, so [src/app.html](src/app.html)
  carries a `<meta name="color-scheme">` and an inline background style **before** the head
  placeholder. Removing them brings back a white flash on every reload. Also beware: never
  write the head placeholder literal anywhere else in that file, comments included —
  SvelteKit only substitutes the first occurrence, and the real placeholder would then stay
  unreplaced, with no error but no stylesheet in production.
- **Component-scoped CSS**, theme variables in [src/app.css](src/app.css). No CSS framework.
- **No runtime dependency** beyond SvelteKit: the header parsers and the masonry are written
  by hand, on purpose.
- Any loop that walks a binary file must be **bounded** — a corrupt media file must never be
  able to freeze the server.
- The `/media` endpoint must never serve a file outside `generations/`: the prefix check
  after `path.resolve` is a security invariant.

### Behaviors to preserve

These points are product requirements, not implementation details:

- **Nothing is cropped or distorted.** The ratio only reserves space; the media is in
  `object-fit: contain` and the real ratio is reapplied as soon as it loads.
- **The newest is at the top**, and tiles read left to right.
- **Videos start muted on hover** and stop, going back to zero, on leave; images stay
  static.
- **Clicking outside the lightbox closes it** (Escape too; ← / → navigate).
- **An unreadable sidecar breaks nothing**: the media stays displayed, the error is
  reported.
- **No flash on reload**: the background is painted from the first frame, and the store's
  initial state is "loading" — a neutral state would flash the "the wall is empty" screen
  before the data arrives.
- **Deletion always asks for explicit confirmation.** It is permanent — the file doesn't go
  through the trash — and takes the sidecar along with the media.
- **A spend never disappears.** Deleting a media file removes a tile from the wall, not a
  euro from the total spent. The price is written to the ledger as soon as the file appears,
  and the `DELETE` route writes the final state **before** erasing: this order is an
  invariant.
- **A provider is a billed company, not a provider+model pair.** The spend page groups on
  `service`; slipping the model in splits one provider's total across several phantom
  lines.
- **The prompt's "copy" button only appears if there is a prompt.** More generally, no
  action should be offered on missing data.
- **Only the interface is translated, never the data.** Prompt, notes, tags, model,
  provider, file names and free-form metadata are shown as written in the sidecar. A
  grouping key must never be a translated label: the unknown provider is the key `''`, and
  its name ("Unknown provider"…) is only resolved at render time — otherwise switching
  language would change the colors and empty the filters.
- **Amounts are shown in the chosen currency, the data stays in its original currency.** The
  currency choice is independent of the language. A total must never add up different
  currencies, or include an amount that no rate can convert without flagging it.
